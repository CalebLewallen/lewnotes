# lewnotes

A self-hostable, single-tenant notes server built on plain files: markdown notes, `todo.txt` tasks, and Excalidraw whiteboards, served by a Go + SQLite core with a Svelte web UI, a CLI, and a TUI.

The defining idea is **data-first**: the HTTP API is the product, and every interface is a peer client over it. Nothing about the web UI is special.

> **Status:** pre-alpha, first usable editing build. The server owns a vault directory, indexes markdown notes into SQLite, assigns stable frontmatter IDs, and requires authentication everywhere. The notes API covers CRUD with ETag/`If-Match`, soft delete, wikilinks/backlinks, rename-with-rewrite, directory create/move, tree/files, FTS5 search, SSE events, and OpenAPI. The web UI can set up the owner, sign in, browse, write in an always-editable live markdown surface with GFM tables, syntax-highlighted fenced code, inline `#tag` styling, and `[[` note completion, edit title/tags/frontmatter attributes, create notes and folders inline from the sidebar, create ghost links, rename with link rewriting, search with ⌘K, and resolve `412` conflicts explicitly. The CLI covers device-token login, notes, search, index status, shell completions, and a machine-readable command catalogue, with the `lewnotes-cli` agent skill embedded. The built SPA is embedded in `lewnotes-core`.

## Layout

```
server/   lewnotes-core: Go HTTP API, vault scanning, SQLite index
cli/      lewnotes: CLI + TUI, plus the shared HTTP client
web/      SvelteKit 5 SPA (Tailwind 4, shadcn-svelte)
docker/   Dockerfile and compose file
```

## Quickstart (dev)

```bash
# API on :8080, with the vault in ./vault and the index in ./data
cd server && LEWNOTES_COOKIE_SECURE=false \
  go run ./cmd/lewnotes-core -vault ../vault -data-dir ../data

# Web dev server on :5173, proxying /api to :8080
cd web && npm install && npm run dev
```

Open <http://localhost:5173>. First boot redirects to `/setup`; create the owner, then the app opens on the notes list. Select a note and start typing: the body is always editable and renders headings, emphasis, code, links, images, and GFM tables as you type, revealing markdown marks only on the active line. Fenced code gets language highlighting; type `[[` to search for a note to link; `#tag` is styled as a tag. The editor fills the remaining viewport, and clicking its blank area places the cursor on the nearest line. The large title is frontmatter `title`; committing it renames the file to match. Use a folder's `+` menu to create a note or folder inline, the row menu to rename, **Properties** for other frontmatter attributes, and `⌘K`/`Ctrl-K` for search. `⌘`/`Ctrl`-click a link in the body to open it. Unresolved wikilinks are dashed and create their note; renames rewrite inbound links; a stale save opens a diff instead of writing. Cookies default to `Secure`, so set `LEWNOTES_COOKIE_SECURE=false` for plain-http localhost — otherwise the browser session will not stick.

## Single binary

`lewnotes-core` serves the embedded SPA at `/`. Rebuild the embed after web changes:

```bash
cd web && npm install
cd .. && bash scripts/build-web.sh
cd server && LEWNOTES_COOKIE_SECURE=false \
  go run ./cmd/lewnotes-core -vault ../vault -data-dir ../data
```

Open <http://localhost:8080>. The committed `server/internal/webui/dist` is generated by the script; Vite remains the HMR dev server.

Setup and login are also available directly: `POST /api/v1/auth/setup` (`{"password":"…","instance_name":"home"}`) and `POST /api/v1/auth/login`; both set the session and CSRF cookies. The end-to-end curl walkthroughs never print secrets: [`server/testdata/scripts/auth.sh`](server/testdata/scripts/auth.sh) and [`server/testdata/scripts/notes.sh`](server/testdata/scripts/notes.sh).

```bash
curl -s localhost:8080/api/v1/health | jq
curl -s localhost:8080/api/v1/auth/status | jq

# The index is private: sign in first (or send a bearer token).
curl -s -c /tmp/lewnotes.jar -H 'Content-Type: application/json' \
  -d '{"password":"…"}' localhost:8080/api/v1/auth/login | jq
curl -s -b /tmp/lewnotes.jar localhost:8080/api/v1/index/status | jq

cd cli && go run ./cmd/lewnotes version --json

# Create a device token in the web UI at /settings/tokens, then:
cd cli && go run ./cmd/lewnotes login --server http://localhost:8080
cd cli && go run ./cmd/lewnotes note list --json
cd cli && go run ./cmd/lewnotes help --json | jq
```

Notes are plain markdown; a note's title is frontmatter `title` (new notes have no duplicate body H1), and the server adds an `id:` ULID to frontmatter on first scan. Drop a `.md` file in the vault or `POST /api/v1/index/rescan` (body `{"full": true}`) to pick up changes made outside the server.

## Tests

```bash
cd server && gofmt -l . && go vet ./... && go test -race ./...
cd cli && go test ./...
cd web && npm run check
cd .. && bash scripts/build-web.sh

# Live API smoke against a running server (setup/login, notes, links, ghost create, directories, rename, search, delete)
LEWNOTES_URL=http://127.0.0.1:8080 server/testdata/scripts/notes.sh
```

The live script uses the server directly; the UI is served by the same binary or by Vite during development.
