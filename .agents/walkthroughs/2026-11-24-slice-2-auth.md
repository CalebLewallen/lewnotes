## Decisions made during the slice

- **Hash session IDs at rest.** The cookie holds 32 random bytes; SQLite stores their sha256. A database leak therefore does not yield live sessions, and sessions are still revocable by lookup.
- **CSRF is server-checked, not just double-submit.** The session row owns the CSRF token; the header must match it, and the same value is mirrored in a readable `lewnotes_csrf` cookie for the SPA. Cookie mutations require the header; bearer requests skip CSRF.
- **Default-deny runs before routing.** The guard wraps the mux, so unknown `/api/v1/*` paths return `401` rather than `404`, and a newly added route is protected unless the allowlist is edited. The test enumerates protected routes.
- **Token scope (spec §18.1) resolved for v1:** one `full` scope. The column, response field, and principal carry it, so narrowing later is middleware work.
- **The embedded URL is advisory.** The server ignores it during verification; the CLI will use it to discover the endpoint (S5).
- **Argon2 parameters live inside the hash string**, so costs can be raised without invalidating existing passwords. Parsing bounds memory/time to keep a corrupted hash from exhausting the process.
- **Rate limits are in memory**: login and setup share 5/min/IP, bearer verification 30/min/IP, authenticated traffic 600/min/principal. Limits reset on restart, which is acceptable for a single-tenant server.
- **Password change revokes every session, then issues a fresh one to the caller**, so the user is not bounced to the login screen. Tokens are revoked only when `revoke_tokens` is set.
- **Login limiter also guards setup**, matching the spec's "setup is rate-limited" note.

## Known gaps / follow-ups

- No CORS handling: same-origin only, as specified. `auth.allowed_origins` is parsed but unused until a cross-origin client exists.
- No session/token pruning job; expired sessions are deleted lazily on authentication, revoked tokens stay as audit rows.
- No `session.revoked` SSE event yet (lands with the event hub in S3).
- `trust_proxy` defaults off; behind a proxy, forwarded headers are ignored until it is enabled, which also affects rate-limit keys and token origins.
- One fixed username (`owner`); the spec's `username` field is not user-editable.
- Deleting `lewnotes.db` now loses the account as well as sessions/tokens — setup must be redone. Content is unaffected.
- Token scopes remain full-access only (documented decision above).
- `X-Lewnotes-CSRF` is required for cookie `POST/PUT/PATCH/DELETE`; S3 clients must send it.
